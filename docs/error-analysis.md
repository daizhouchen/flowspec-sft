# FlowSpec 模型错误分析

## 分析范围

本文记录固定数据切分上的失败模式和修正过程。所有数字来自保存的预测文件与统一评测脚本；标准测试集和挑战集仍为 `pending_user_review`，因此结果保持 provisional。

## 第一轮：仅列工具 ID 的系统提示

Qwen3-1.7B 使用 4-bit QLoRA、LoRA rank 16、两轮训练，在 1,600 条训练样本上完成 200 步更新。训练过程本身稳定：训练损失为 0.0391，最终验证损失为 0.3529，峰值分配显存为 3.577 GiB。

加入确定性 JSON 与参数格式修复后，第一轮在标准测试集上的结果为：

| Schema | DAG | 沙箱通过 | 工具 F1 | 参数 F1 | 依赖边 F1 | 语义结构得分 |
|---:|---:|---:|---:|---:|---:|---:|
| 0.956 | 0.956 | 0.908 | 0.639 | 0.459 | 0.248 | 0.449 |

挑战集上的语义结构得分进一步降至 0.321。结果说明结构可执行并不代表工作流语义正确。

## 主要失败模式

1. **参数名漂移：**模型把 `message.send.channel` 写成 `recipient`，把 `input_from` 写成 `input`，或者遗漏 `feedback.search.date_range`。
2. **工具别名与虚构：**模型输出 `text.analyze`，而注册表中只有 `sentiment.analyze`。
3. **过度规划：**原任务只要求检索、风险分析和人工确认，模型额外加入报告、邮件或导出步骤。
4. **失败路径展开错误：**模型把 `on_failure` 展开成普通节点，导致依赖边和工具集合偏离目标。
5. **JSON 收尾错误：**少量长输出出现括号错配、重复对象或截断。直接丢弃这些样本会把格式失败与语义失败混在一起。

## 第二轮：完整工具契约，单一训练结构

第二轮将 18 个工具的必填参数写入系统提示，但训练数据仍集中在四类重复结构。200 步训练后的验证损失为 0.3641，标准测试集 Schema / DAG 合法率均为 1.000，沙箱通过率为 0.976；工具 F1 0.571、参数 F1 0.560、依赖边 F1 0.140，语义结构得分只有 0.424。格式正确性已经解决，但结构泛化反而下降，因此停止挑战集长跑，并把这一轮保留为数据课程消融。

## 最终轮：多样化课程与拓扑校验

最终训练集扩展为 12 个互不泄漏的流程家族，覆盖全部 18 个工具；测试与挑战模板族均不出现在训练集。校验器增加 `input_from` 上游约束、失败处理器参数检查，并把依赖边按“工具到工具”的语义拓扑计分，避免节点命名差异污染结构指标。

| 数据集 | Schema | DAG | 沙箱通过 | 工具 F1 | 参数 F1 | 依赖边 F1 | 语义结构得分 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 标准测试集（250） | 1.000 | 1.000 | 1.000 | 0.856 | 0.844 | 0.680 | 0.793 |
| 挑战集（100） | 1.000 | 1.000 | 1.000 | 0.818 | 0.801 | 0.376 | 0.665 |

相较 few-shot + 校验器，标准测试集语义结构提高 11.95 个百分点，沙箱通过率提高 14.8 个百分点。训练损失从第一轮 0.0391 降至 0.0221，验证损失从 0.3529 降至 0.1914。四项预设验收门槛全部通过。

## 修正方案

- 训练、离线评测和 API 共用同一份系统提示，明确 18 个工具的中文职责、必填参数和允许参数。
- 明确要求只选择任务需要的工具；`trigger` 只允许出现在顶层；失败通知使用 `on_failure`，不得生成额外失败节点。
- JSON 提取器优先读取第一个完整对象，并对括号错配与常见收尾错误做有限、可记录的确定性修复。
- 校验器只修正可确定的格式问题，例如参数别名、节点 ID、空依赖和已知工具别名；无法确定的语义错误最多反馈模型一次。
- 把工具、参数槽位与依赖边 F1 的均值定义为“语义结构得分”，与 Schema、DAG 和沙箱通过率分开报告。

## 剩余错误与边界

- 挑战集依赖边 F1 为 0.376，仍明显低于标准集。模型通常选对工具和参数，但会把可并行节点串行化，或漏掉汇聚节点的一条输入边。
- exact structure 在标准集为 0.340、挑战集为 0。严格全图一致对节点组合非常敏感，因此不能只报告合法率。
- 确定性修复不会凭空选择业务工具，也不会把低语义得分包装成成功；最终 SFT 标准集没有触发修复，但线上未知输入仍可能进入一次模型反馈或人工确认。
- 数据均为原创合成工作流，测试集与挑战集尚待作者逐条人工复核；所有数值为 provisional，不能外推为真实业务成功率。

GGUF Q4_K_M 已在远程 CPU 上通过有限单轮冒烟，并完成 `llama-server → FastAPI → compile → simulate` 端到端验证。5 节点样例全部执行成功，但 CPU 编译耗时约 70.75 秒，说明当前部署适合作品集复现与低频受限 Demo，服务化仍需批处理、缓存或更强推理硬件。
