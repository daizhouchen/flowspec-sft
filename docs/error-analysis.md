# FlowSpec 模型错误分析

## 分析范围

本文记录固定数据切分上的失败模式和修正过程。所有数字来自保存的预测文件与统一评测脚本；标准测试集和挑战集仍为 `pending_user_review`，因此结果保持 provisional。

## 第一轮：仅列工具 ID 的系统提示

Qwen3-1.7B 使用 4-bit QLoRA、LoRA rank 16、两轮训练，在 1,600 条训练样本上完成 200 步更新。训练过程本身稳定：训练损失为 0.0391，最终验证损失为 0.3529，峰值分配显存为 3.577 GiB。

加入确定性 JSON 与参数格式修复后，第一轮在标准测试集上的结果为：

| Schema | DAG | 沙箱通过 | 工具 F1 | 参数 F1 | 依赖边 F1 | 语义结构得分 |
|---:|---:|---:|---:|---:|---:|---:|
| 0.956 | 0.956 | 0.908 | 0.639 | 0.459 | 0.248 | 0.449 |

挑战集上的语义结构得分进一步降至 0.321。结果说明结构可执行并不代表工作流语义正确。

## 主要失败模式

1. **参数名漂移：**模型把 `message.send.channel` 写成 `recipient`，把 `input_from` 写成 `input`，或者遗漏 `feedback.search.date_range`。
2. **工具别名与虚构：**模型输出 `text.analyze`，而注册表中只有 `sentiment.analyze`。
3. **过度规划：**原任务只要求检索、风险分析和人工确认，模型额外加入报告、邮件或导出步骤。
4. **失败路径展开错误：**模型把 `on_failure` 展开成普通节点，导致依赖边和工具集合偏离目标。
5. **JSON 收尾错误：**少量长输出出现括号错配、重复对象或截断。直接丢弃这些样本会把格式失败与语义失败混在一起。

## 修正方案

- 训练、离线评测和 API 共用同一份系统提示，明确 18 个工具的中文职责、必填参数和允许参数。
- 明确要求只选择任务需要的工具；`trigger` 只允许出现在顶层；失败通知使用 `on_failure`，不得生成额外失败节点。
- JSON 提取器优先读取第一个完整对象，并对括号错配与常见收尾错误做有限、可记录的确定性修复。
- 校验器只修正可确定的格式问题，例如参数别名、节点 ID、空依赖和已知工具别名；无法确定的语义错误最多反馈模型一次。
- 把工具、参数槽位与依赖边 F1 的均值定义为“语义结构得分”，与 Schema、DAG 和沙箱通过率分开报告。

## 边界

确定性修复不会凭空选择业务工具，也不会把低语义得分包装成成功。第二轮实验使用完整工具契约重新训练，并在同一标准测试集、挑战集和 zero/few-shot 对照上复算；若语义增益不足 8 个百分点，结果表将保留为负结果。
